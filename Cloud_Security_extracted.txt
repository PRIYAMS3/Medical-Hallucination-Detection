===== PAGE 5 =====
Identity and Access Management (IAM)
• Identity and Access Management is a critical component of cloud 
security that ensures only authorized users can access resources. 
• It involves authentication (verifying identity) and authorization (granting 
permissions).
• IAM systems implement mechanisms such as:
• Role-Based Access Control (RBAC) 
• Multi-Factor Authentication (MFA) 
• Least privilege principle 
• Improper IAM configuration is one of the leading causes of cloud 
security breaches.
===== PAGE 6 =====
Data Security
• Data security involves protecting data at all stages: at rest, in transit, and in use.
• Encryption is widely used:
• Data at rest is protected using algorithms such as AES 
• Data in transit is secured using protocols like TLS 
• Emerging techniques such as confidential computing protect data during processing 
• Backup and disaster recovery strategies are also essential to ensure data availability 
during failures or attacks.
Network Security
Network security in cloud environments focuses on securing communication between systems. 
This is achieved through:
• Virtual Private Clouds (VPCs) 
• Network segmentation 
• Firewalls and security groups 
• Intrusion Detection and Prevention Systems (IDS/IPS) 
These mechanisms help prevent unauthorized access and detect malicious activities.
===== PAGE 7 =====
Application Security 
• Applications deployed in the cloud must be designed securely to prevent 
vulnerabilities. This includes:
• Secure coding practices 
• Regular patch updates 
• Vulnerability assessment and penetration testing 
• Modern cloud applications often use microservices and APIs, which require 
additional security measures such as API gateways and rate limiting.
Compliance & Governance
Organizations using cloud services must comply with various regulations and standards such as:
• ISO 27001 
• GDPR 
• HIPAA 
Compliance ensures that data is handled securely and legally. Governance policies define how 
resources are accessed, monitored, and audited.
===== PAGE 8 =====
Threats and Vulnerabilities in Cloud
• Cloud environments face a variety of threats. One of the most common is data 
breaches, often caused by misconfigured storage systems. 
• For example, publicly accessible storage buckets have led to significant data leaks.
• Other major threats include:
• Account hijacking due to stolen credentials 
• Insider threats from authorized users 
• Denial-of-Service (DoS) attacks 
• Malware injection in cloud workloads 
• Many cloud security incidents are not due to provider failure but due to user 
misconfiguration.

Layered Cloud Security Architecture
• Cloud security works in layers (defense-in-depth)
• Each layer addresses specific risks and ensures end-to-end protection.
Physical Layer
• Data centers, hardware, cooling systems 
• Managed by providers like Amazon Web Services 
• The lowest layer consisting of data centers, servers, and storage hardware
Security Measures:
• Surveillance systems (CCTV, biometrics) 
• Restricted physical access 
• Environmental controls (cooling, fire suppression) 
• Responsibility is Fully managed by cloud provider 
• Failure here → complete system compromise

===== PAGE 17 =====
Zero Trust Architecture
• Traditional security models assumed that everything inside an
organization’s network could be trusted. However, with cloud
computing, remote work, and mobile access, this assumption is no
longer valid.
• Zero Trust eliminates implicit trust and requires continuous verification
of every user, device, and request, regardless of whether it originates
inside or outside the network.
===== PAGE 18 =====
Principles of Zero Trust
• Zero Trust is built on three fundamental principles:
1. Verify Explicitly
• Every access request is authenticated and authorized using:
• User identity 
• Device health 
• Location 
• Risk level 
2. Least Privilege Access
• Users are given only the minimum access required to perform their tasks.
3. Assume Breach
• The system assumes that attackers may already be present and continuously 
monitors activity.
===== PAGE 19 =====
Working of Zero Trust 
• User requests access to a resource 
• System verifies identity (login + MFA) 
• Device posture is checked 
• Context is evaluated (location, behavior) 
• Access is granted with limited privileges 
• Activity is continuously monitored 
Access can be revoked instantly if suspicious behavior is detected

Authentication Models
• Authentication is the process of verifying the identity of a user or 
system. 
• Before access is granted, the system must answer: “Who are you?”   
Classification of Authentication
Authentication can be divided into three categories:
1. Authentication Methods: (How identity is verified)
2. Authentication Models: (How authentication is managed across systems)
3. Security Enhancements: (How authentication is strengthened)
===== PAGE 24 =====
Authentication Methods
• These directly verify identity:
• Password-based 
• Biometric (fingerprint, face) 
• Certificate-based 
• Token-based 
These answer “Is this user genuine?”
Authentication Models
These define how authentication works across systems:
• Multiple Login (Traditional) 
• Single Sign-On (SSO)
• Federated Authentication 
These answer “How is access managed across multiple applications?”

Multiple Authentication (Traditional Model) 
• Multiple Authentication (or Traditional Login) requires users to log in 
separately to each application. 
• Working: 
• User accesses Application A → enters credentials 
• User accesses Application B → logs in again
• Each system maintains its own authentication database  
• Advantages
• No dependency on central system 
• No single point of failure
• Disadvantages
• Poor user experience 
• Password fatigue 
• Higher chance of weak/reused passwords
===== PAGE 27 =====
Single Sign-On (SSO)
• SSO allows a user to log in once and access multiple systems without 
re-authentication.
• SSO does not verify identity itself. It uses underlying authentication 
methods
How SSO Works
• User logs in once 
• Identity is verified (e.g., password + OTP) 
• System creates authentication session/token 
• Same identity is reused across applications 
No repeated login required
SSO is NOT an authentication method. 
SSO is an authentication model/ architecture
It depends on: Password, Biometrics, MFA
===== PAGE 28 =====
Federated Authentication 
• Federated Authentication allows users to access systems across 
different organizations using a trusted identity provider. 
Working:
• User tries to access an application (Service Provider)
• Redirected to Identity Provider
• User logs in once
• Identity Provider sends authentication token
• Access granted 
• Examples
• Login with Google 
• Login with Microsoft

Password-Based Authentication
Uses username and password
• Issues:
• Weak passwords 
• Reuse across systems 
• Vulnerable to attacks 
• Still widely used but less secure
Certificate-Based Authentication
Uses digital certificates to verify identity
Example: SSL/TLS client certificates 
Advantages:
• Strong security 
• No password required
Token-Based Authentication
Uses tokens instead of passwords after login
Examples:
JWT (JSON Web Token) 
Session tokens 
Used in APIs, Cloud applications
Biometric Authentication
Uses physical or behavioral traits
Examples:
• Fingerprint 
• Face recognition 
• Iris scan 
Difficult to replicate

Multi-Factor Authentication (MFA)
Requires multiple authentication factors
Types:
• Knowledge (password) 
• Possession (OTP/device) 
• Inherence (biometric) 
Strong security enhancement
Passwordless Authentication
Authentication without passwords
Methods:
• Biometrics 
• Security keys 
• Magic links 
Advantage:
Eliminates password attacks
Adaptive Authentication
Authentication based on risk/context
Example:
• Normal login → allowed 
• Suspicious login → extra verification 
Dynamic and intelligent
Kerberos Authentication
Ticket-based authentication system
Used in: Enterprise environments 
• No repeated password transmission
